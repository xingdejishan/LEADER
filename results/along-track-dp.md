## 判定（四个问题）

**1. 能不能替代门控？不能，但两端都不是平的。** 完全不加阈值（η=0）时，λ=0.01 给出 0.1882 / >1m 360 / >5m 273：两个计数都比门控的 366 / 284 好 （分别少 6 和 11 帧），MPE 却比门控差 0.0039。手工阈值换来的正是这 0.004 米平均误差，序列先验单独做不到同样的折中。

**2. 在门控之上再加序列先验值多少？0.0001–0.0018 米，而且随 η 变大迅速消失。** 同 η 下最优 λ>0 相对 λ=0：η=0 → -0.0018，η=0.005 → -0.0011，η=0.01 → -0.0007，η=0.015 → -0.0001，η=0.02 → -0.0003，η=0.03 → -0.0001，η=0.05 → -0.0001。

**3. 比 0.1843 / 1.4018 / 366 这一行如何？MPE 上赢 0.0013，但只有 0.0001 是 DP 的。** λ=0.001、η=0.015 给出 0.1830 / 366 / 284（MOE 1.4047，因为 DP 不动旋转；把冻结的旋转表用在位姿与逐帧输出逐位相同的那些修正帧上，得到 MOE 1.4019、ok 80.6%。同口径的 0.1843 只差 MPE 一项，而这点差距里 η=0.01→0.015 贡献 0.0012、λ 贡献 0.0001。

**4. 尾部：计数上略有帮助，长爆发段完全不动。** 不加阈值（λ=0.01、η=0，修 20% 帧）时>1m 360、>5m 273，都优于门控的 366 / 284，但 MPE 0.1882 已超出前端 0.1876 的预算；在预算内（λ=0.01、η=0.002，MPE 0.1871）仍是 >1m 363、>5m 273。改善的 11 帧全部落在爆发段之外：最长的 271 帧爆发段（2012-02-12，前端 8.45 米）门控与 DP 都是 8.45，35 帧那段从 3.02 米略升到 3.14 米，其余两段逐位相同。>10m 从 7 到 6。

**机制**：DP 把门控 7719 帧的修正在 4396 帧上重做——丢掉 43% 的有害修正，同时留下 70% 的有益修正，有害帧数从 2505 降到 1438，两者在总误差上几乎抵消，所以 MPE 只动 0.0001。被抑制的是单帧幅度很小、且与邻帧不一致的修正，不是灾难帧；灾难帧要么本来就修得动（burst 2-4），要么谁都修不动（burst 0）。

## 口径与诚实边界

- 所有数字都在同一批 104,728 帧上、用同一套真值算，没有留出集；配置是从 91 个格点里挑 MPE 最小的，所以 0.0001–0.0005 的差别应当看作选择噪声，而不是可复现的增益。
- DP 只动平移，MOE/ok 与前端相同（1.4047 / 80.2–80.4%）。当前最好那一行的 1.4018 / 80.6% 来自冻结的旋转精修，它与平移无关，但只能用在"位姿与逐帧输出逐位相同"的修正帧上（本例 97%），所以 DP 行的 MOE 只能报到 1.4019 这种近似值。
- 复算的校验：逐帧在"该帧自己的 argmin 单元"精修，与项目已有 P_search 逐位相同（120 帧校验，最大偏差 0.0000 m）；λ=0、η=0.01 复现门控的 7719 帧与 0.1843；参考四行与项目记录逐位一致。
