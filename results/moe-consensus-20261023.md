# 把多参考一致性验收放回并列结构（2026-10-23，纯 CPU，全部实测）

一句话：验收加回来了，**救援没回来**。全量 **1.1826 / 2.2932**（上一轮无位姿版 1.1727 / 2.2551，
级联 0.8585 / 2.1674）；门开 84 帧救回 **5.62 米**（上一轮 5.80、级联 11.57）；
旋转相关全量 **+0.0151**、门开子集 **−0.0105**，都小于 0.1。视觉假设数 **899 → 567**。

## 1. 唯一改动：验收放回视觉专家的输出处

| 文件 | 改动 |
|---|---|
| `visual_expert.py` | 新增 `PoseFreeVisualExpert.candidates_posefree(image, scan)`：**完全无位姿**的 CLS 全库 top-20 检索（沿用 `select_references_posefree`，位置球那套代码保留但流程不再调用），冻结的匹配/投影/`_hypotheses()` 逐位复用，为每个通过共识的解算一次 `branch.verify()` 的 fair 分。上一轮的位置球方法一行未删，只是不再被调用 |
| `moe_parallel.py` | 视觉假设的输出处（原来 `visual = expert.hypothesize(...)` 那一行）换成 `accept_consensus()`：先按共识筛，再按 fair 分排序取最高；没有共识组就返回 `None`，该帧只把几何假设交给仲裁。`--psradius` 换成 `--accept consensus\|pnp`（`pnp` 只作复现自检，默认 `consensus`） |

验收规则（常数全部从冻结 plan 读，没有重打）：

```
候选解 = 该帧 20 个参考各自的 PnP 解 ∪ 全集解 ∪ 每 25 m 簇解，均过 provider 合格判据
共识组 = 至少有 2 张参考的合格解落在该解 5 m / 10° 内（并集计参考数）
唯一假设 = 共识组内 fair 分最高者
无共识组 → 视觉专家不输出，仲裁只用几何假设
```

diag 里逐帧记下的常数：`consensus_need=2`、`consensus_translation_m=5.0`、
`consensus_rotation_deg=10.0`。仲裁、并集支撑集、`k·σ_C`（k=8.4）、沿轨搜索、评分一行未动。

## 6. 差在哪（逐帧实测）

验收从 899 个假设里拿掉 332 个（门开 49→37，拿掉 12 个）。逐帧核对的全部结果是：

| 帧 | 变化 | 说明 |
|---|---|---|
| 760 | 6.07 → **0.19 m**（新采纳） | fair 分在共识组里挑中的解比"内点最多"的解好得多 |
| 996 / 997 | 0.30 → 0.24 / 0.82 → **0.25 m** | 同上，小幅变好 |
| 737 / 750 | 0.08 → 0.16 / 0.18 → 0.33 m | fair 挑中的解比内点排序的解略差 |
| 1428 | 2.37 → 7.07 m | 同上，变差 4.7 米 |
| **1429** | 2.60 → **18.89 m**（假设被验收否掉） | 3 个合格解、0 个过共识；这是唯一一个被验收真正丢掉的救援 |
| 732 | 9.31 → 9.41 m | 上一轮采纳的本身就是 9.3 米的错解，丢掉后回到几何 |
| 1227 / 1229 | 443 / 444 m 不变 | 合格解 0 个，验收无解可筛 |

净结果：全量 MPE 变的 0.0099 米几乎全部来自 1429 一帧（(18.89−2.60)/1502 = 0.0108）；
门开救回少的 0.18 米同理（(18.89−2.60)/84 = 0.194）。也就是说，
**这一版的差别不是"共识把错盆地拒掉"，而是"共识偶尔把对的解一起拒掉，又用 fair 分换掉了少数解"。**

假设本身确实更干净了：位置误差中位 5.49 → **1.00 米**，p90 176.9 → 79.5 米，
≤1 米 282 → 285 帧（前提是总供给少了 37%）；门开帧的假设中位反而变差（17.45 → 25.52 米），
因为门开帧里被留下的都是硬帧。

## 7. 判定

**没达到。** 门开救回 5.62 米，离"接近 11 米"差 **5.95 米**（只有级联的 48.6%，比上一轮还少 0.18 米）；
旋转相关这一半达标（全量 +0.0151、门开 −0.0105，逐分量口径都 <0.1）。
差的地方不在验收本身：1227/1229 两帧在无位姿 top-20 检索下合格解数为 0，验收再严也变不出假设；
而验收在其余帧上是有代价的——它拿掉 332 个假设、丢掉 1429 这一个真实救援，换回的净收益接近零。

## 8. 偏离、崩溃、复现

1. **fair 分的打分范围**：冻结 provider 只给"内点最多的前 8 个"打分，本版给**所有过共识的**候选打分
   （共识组本身很小：每帧过共识数中位 0、p90 4、最大 11，超过 8 的只有 6 帧）。除此之外 fair 的
   公式、0.4 米查询体素、0.3 米阈值、36 个方位格、排除自身参考，全部是冻结实现。
2. **查询点云用帧自己的原始扫描**（按视觉支路的方式解码），没有复用搜索那份预处理点集——与冻结
   `hypothesize` 一致。
3. **1 帧瞬时 I/O 失败**：idx 675（`2012-02-19/1329677332473519`，非门开帧）在 fair 校验读缓存时抛
   `BadZipFile('File is not a zip file')`，该帧无假设、按几何输出。单独重跑该帧不复现
   （`n_hyp=11 n_qual=2 n_acc=0`），即它本来也不会有假设，结果不受影响。
4. **自检**：`--accept pnp`（上一轮的"内点最多"规则）在 11 帧上与上一轮产物 **逐位相同**
   （`max|Δ| = 0.0`，含 1227/1229/1230 与 7 个门开帧），证明除验收外整条路径没变；
   本版 1486 个未采纳帧的输出与"只走路线三" **逐位相同**（`max|Δ| = 0.0`）。
5. **未动的文件**：`arbitration.py`、`three_route_unified.py`、`visual_branch.py`、`stages/`、
   `README.md`、`STRUCTURE.md`，以及硬链接共享的 `e2e-moe-20261020-v1`（只读）。
   所有写入都是先落 `/tmp` 再 `mv`。
6. **耗时与资源**：全量 1502 帧、6 个 worker、`nice -n 19`、`CUDA_VISIBLE_DEVICES` 置空、
   leader 环境的 python，单帧 8–22 秒，**总计 49 分钟**（05:12 → 06:01）。
