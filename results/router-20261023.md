# 可学习三路 Router：实现、四折留一实测与失败归因（2026-10-23）

一句话：**Router 已实现并接入（三路离散选择、43 维跨模态特征、7171 参数 MLP、按日期留一），
但四折留出 MPE 1.5093 / MOE 2.3069，比现有的 0.8463 / 2.1299 差 0.663 米 / 0.177 度；
门开 84 帧只救回 47.5 米，现有的 973.5 米基本全丢。**按题面约定停在两轮，不再调参，下面是实测与归因。

## 3. 标签与防泄漏

- 损失 `L = 平移误差/1m + 旋转误差/1°`（另报单指标版本），标签取损失最小的一路；两路都差于 T0 时取 T0。
- 四折**按日期留一**（4 个日期：2012-02-12 / 02-19 / 03-31 / 05-26），训练集与评测集不同日；
  特征标准化的中位与 IQR、类别先验、早停轮数（内层取训练日期各自时间序后 20%）都只用训练日期算。
  推理不含任何 GT。
- 数据复用：`router_dump.py` 只**加载**现有专家，没有重跑视觉推理之外的任何东西；校验通过——
  dump 的旧判决位姿与 `live-parallel-full.npz` **1502/1502 逐位相同**（max |Δ| = 0.0），
  几何路与 `par-route3.npz` 同样逐位相同，视觉假设在 1498/1502 帧存在。

## 6. 选择分布与一致率（Router 第二轮）

- 三路分布：T0 **0** 帧 / T_geo 1236 帧 / T_vis 266 帧（旧判据：T_geo 1470 / T_vis 32）。
- 与旧判据一致率：**81.6%**（门开 73.8%，门外 82.1%）。
- 门开 84 帧的标签是 T0 3 / geo 49 / vis 32；Router 选 T0 0 / geo 67 / vis 17。
  即：GT 说该换视觉的 32 帧里它只换了 **11 帧**，另有 6 帧在标签说 geo 时换了视觉。
- 按类命中率：T_vis 被选 266 次，标签同意 48%；T_geo 被选 1236 次，同意 71%；T0 一次没选。
- 第一轮（逆频率类别权重）三路分布 T0 531 / geo 508 / vis 463，与旧判据一致率仅 34.8%，
  且 T0 的 531 次里有 348 次与标签不符——类别权重把决策推向少数类，是这个配置崩掉的主因。

## 7. 三特征对照（自查是否退化成旧判据）

同一套四折流程，只喂 `c_geo`、`c_vis`、`sigma_c` 三个量：MPE 1.2865 / MOE 2.4225，门开 6.4717，
救回 944.2 m，分布 T0 0 / geo 1115 / vis 387，与旧判据一致率 76.4%，**与 43 维 Router 的一致率 80.4%**。

结论分两句，都要写清：
1. **决策确实不同**：两套 Router 在 19.6% 的帧上给出不同选择，说明 43 维特征没有退化成那三个数。
2. **但性能没有因此变好**：三特征对照的 MPE 比 43 维 Router **更好**（1.2865 对 1.5093），
   MOE 更差（2.4225 对 2.3069）。也就是说，本轮没有任何证据表明这些跨模态特征带来了可用的判别力；
   "特征设计没有退化"的自查**不通过**。

## 8. 判定、差距与原因

**判定：Router 没有达到现有水平。** 全量 MPE 1.5093 对 0.8463（差 +0.663 米，78%），
MOE 2.3069 对 2.1299（差 +0.177 度），门开救援 47.5 m 对 973.5 m（只剩 4.9%）。
三路 Oracle 0.5636 / 1.7665 说明标签空间本身有 0.28 米的余量，差距不是标签不可达，而是学不出来。

原因（按证据强弱排序）：

1. **标签定义与指标结构错配（主因）。** 指标是全量 1502 帧的均值，而它的走势由约 32 帧决定；
   三路 argmin 标签却把 1502 帧基本等权。于是模型把力气花在"普通帧上视觉略胜"的 429 个视觉标签上
   （选中 266 次、只有 48% 对），而在真正决定指标的 32 个门开帧上只有 34% 的召回。
   第二轮用 `w = clip(损失极差, 0.05, 1)` 做代价加权也没能翻转：极差的全量均值已经到 0.873，
   门开帧直接饱和在上限 1，与"普通但差一点"的帧量级拉不开，等权问题只被削弱了一点。
2. **第三路 T0 实际退化。** 按"显著差于 T0 才取 T0"加 0.25 余量后，T0 标签只剩 64 帧（4.3%），
   模型干脆一次都不选；不加余量时（第一轮）又选了 531 次、其中 348 次与标签不符。
   两种极端都说明这个候选在现有特征下没有稳定的可学边界。
3. **样本量。** 每折留出一个日期，训练集里门开帧合计约 63 个，而这些帧决定了指标。
4. **不是特征不足的正面证据，而是反证。** 三个数的对照在 MPE 上更好，说明本轮 43 维特征里
   真正有用的信息没超出 `C_geo/C_vis/σ_C` 太多；新增的跨模态量（平移差、旋转差、支撑点数、
   重投影、内点率、一致数）没有把它们变成可分的问题。

如果还要继续，最有价值的下一步不是调网络，而是改标签的功效：用"决策损失"（选错一路的代价）
做代价敏感训练或用序回归直接预测各路的损失，而不是三分类 argmin。

## 9. 成本、崩溃与偏离

| 项目 | 实测 |
|---|---|
| 特征 dump（三路位姿 + 43 维；含视觉专家全量调用） | 3 分片 × 3–4 进程 = 12 进程，GPU **3/4/5**（未碰 0/1/2/6/7），每卡峰值 **7.3–7.8 GB**，单次全量墙钟 **11–13 min**；含崩溃后重跑合计约 **26 min** |
| Router 训练（四折 × 3 seed + 对照 + 交付权重） | **28.5 s** 墙钟，**CPU**（7k 参数不需要 GPU），显存 0 |
| 单进程视觉 fmri 参考 | 与既有报告一致（中位 ~3 s/帧，CPU 受限，GPU 利用率 0–16%） |

偏离与崩溃（附原文）：
1. `ValueError: cannot convert float NaN to integer`，位置 `router_dump.py:471 supp_vis=int(s_v)`——
   无视觉假设时支撑数是 NaN。3 个分片里有 2 个整片丢失，修好后重跑。
2. 第二轮首跑标签余量写反（`0 if L0 - be < t0margin`），把 T0 标签推到 644 帧（42.9%），
   按题面"两路都显著差于 T0"的原意改成 `(be - L0) > t0margin` 后重跑；本报告的表都是修正后的。
3. `IndexError: too many indices for array: array is 1-dimensional, but 2 were indexed`
   （代价面 picks 是元组，索引少了一层）与 `ValueError: too many values to unpack (expected 3)`
   （诊断写盘循环没跟着四元组改），都在小样本自检阶段发现并修正，未进入全量。
4. `matmul: Input operand 1 has a mismatch in its core dimension 0 ... (size 64 is different from 43)`——
   推理端按 torch 的 (out,in) 权重存法漏了转置。修正后接线自检：**`--router` 走通，20/20 帧的选择与
   位姿与离线计算逐位相同**。
