# 更严格的正确对应点离线融合诊断

在已有的共享几何精修后端上，固定每帧 v1 起点、LiDAR 池、权重、初始支持集和优化预算，仅替换视觉对应点。没有重新训练，也不使用 GT 构造求解起点。

筛选条件沿用已有指标：相机参考位姿下正深度、重投影误差 <10px，且预测三维点与现有稀疏监督目标的距离 <1m。点必须来自 GLACE 预测，不能用监督目标替代预测。相同图像空间块数量、相同点数的随机子集作为控制。

这仍是 oracle 离线诊断：使用了参考位姿和稀疏监督，不能在部署时直接获得；监督目标未独立核验，因此不能把筛出的点称为已知绝对正确的三维对应点。

| 方法 | 1m/2° 成功数 | 0.5m/1° 成功数 | 相对 v1 救回 / 损害 |
|---|---:|---:|---:|
| 原 v1 | 117/148 | 42/148 | 0 / 0 |
| 同后端 LiDAR-only | 115/148 | 36/148 | 1 / 3 |
| selected 严格 oracle | 121/148 | 43/148 | 7 / 3 |
| selected 匹配随机子集 | 118/148 | 36/148 | 6 / 5 |
| balanced 严格 oracle | 122/148 | 41/148 | 8 / 3 |
| balanced 匹配随机子集 | 119/148 | 39/148 | 5 / 3 |

所有方法在全部 148 帧均实际执行精修。selected 筛后点数的逐帧中位数为 13，5 帧无点、38 帧少于 6 点；balanced 中位数为 11，4 帧无点、48 帧少于 6 点。没有视觉点时仍运行同预算的 LiDAR-only 目标，不把跳过精修作为零损害对照。

在当前已使用的开发集，严格 oracle 相对原 v1 分别净增 4、5 帧，相对匹配随机子集均净增 3 帧，支持预测中存在可帮助融合的信息。但两组均损害 3 个 v1 成功帧，balanced 的严格门限还低于 v1；因此不是稳定融合收益或完美置信度上限，也没有证明能在推理时识别这些点。

较早的只按重投影筛选的 oracle 在相同起点精修中为 122/148、123/148。增加三维阈值没有进一步提高宽松门限成功数，可能同时损失点数与覆盖；本轮不据此搜索新阈值。

复现命令（本地包根目录，新输出目录）：

```powershell
.\.venv\Scripts\python.exe local.py refine-ablation --variant selected --oracle-quality joint3d --out outputs/oracle-joint3d-new
```

完整输出：`outputs/oracle-joint3d-selected`、`outputs/oracle-joint3d-balanced`；本目录保存汇总及冻结协议。使用此前固定回放的像素与稀疏支持范围，本实验是控制变量诊断，不代表全图可部署流程的成绩。
