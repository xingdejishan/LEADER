# 64 维子空间推到上限：位姿加权 + 量化感知 + 正交旋转

目标不变：在不动 V7、不动 MoE 的前提下，把 SAM 的 256 维特征压到 64 维，尽量不掉精度，
每帧 128 KiB。上一轮线性子空间只做到 1453 帧（8 位），这一轮做到 **128 KiB 下 1472 帧**。

## 结果

| 方案 | 每帧 | 位置误差 | 旋转误差 | 达标帧 |
|---|---:|---:|---:|---:|
| SAM 原特征 | 2 MiB | 1.3204 | 1.9875 | 1482 |
| PCA-64 八位 | 256 KiB | 1.3230 | 2.0467 | 1464 |
| PCA-64 四位 | 128 KiB | 1.3207 | 2.0468 | 1461 |
| 图像学生八位（此前最好） | 256 KiB | 1.3285 | 2.0255 | 1463 |
| 图像学生四位 | 128 KiB | 1.3301 | 2.0265 | 1458 |
| 线性子空间八位（第一版） | 256 KiB | 1.3245 | 2.0048 | 1450 |
| 位姿加权八位 | 256 KiB | 1.3209 | 1.9911 | 1464 |
| 位姿加权四位 | 128 KiB | 1.3247 | 2.0278 | 1454 |
| 量化感知四位 | 128 KiB | 1.3229 | 1.9843 | 1455 |
| **旋转基四位（本结果）** | **128 KiB** | **1.3213** | **1.9935** | **1472** |

2501 帧有效配对，冻结 V7 前端，三种变体共享点云、初值与图像，真值只在评分进程读取。

## 怎么做到的

**一、把目标换成 V7 真正读取的量。**不再对齐 256 维张量，而是对齐 V7 在投影点上实际
消费的 32 维观测描述子。冻结 SAM 特征，只学一个 256→64 的线性子空间，从 PCA-64 的闭式解
初始化。描述子余弦误差降到 0.005，但达标帧只有 1450——平均变好、尾部变差。

**二、按位姿敏感度加权。**达标是尾部指标，而逐点描述子误差被大量靠近传感器的点主导，
这些点的旋转力臂几乎为零。用每个点的距离（旋转雅可比的模）作权重，再加一项最差点的惩罚。
八位从 1450 提升到 1464，与 PCA 持平，且旋转误差从 2.0048 降到 1.9911。

**三、量化感知训练。**四比特下位姿加权版本掉到 1454，说明任务对齐的基把信息压得更密，
粗量化伤得更重。把四比特量化器放进训练图（直通估计），四比特回到 1455。

**四、量化前先做正交旋转（决定性的一步）。**子空间本身不变——对基右乘正交矩阵 Q、
对码右乘 Q 的转置，乘积完全相同，实测往返误差为 0——但每个通道的动态范围变了，
同样四比特的开销分布不同。用哈达玛矩阵旋转后，**四比特从 1455 跳到 1472，超过了
PCA-64 用两倍存储得到的 1464**。

## 控制实验

同一个子空间换随机正交旋转：四比特只有 1459，比哈达玛低 13 帧。所以增益来自旋转的选择
（把能量摊平到各通道），不是子空间本身或评测噪声。

## 局限

- 只验证 V7 前端，没有回放 MoE 路由；机制上已知位置误差会被几何支路抹平，特征差异主要
  体现在旋转上。
- 单种子、单次训练，没有做超参搜索；正交旋转只试了哈达玛和一个随机对照。
- 仅在 NCLT 上；Oxford 未验证。
- 这条线仍然是“SAM 特征的子空间”，部署时仍然需要 SAM 编码器；去掉 SAM 需要配合图像学生。

## 复现

`src/train_head3.py`（位姿加权）、`src/train_head4.py`（量化感知）、`src/rotate_basis.py`
（正交旋转）、`src/eval_compact.py --bits 4`（评测）。结果在 `results/`。
