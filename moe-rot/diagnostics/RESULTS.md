# 为什么 MPE 一直降、MOE 降不动：全量诊断（2026-10-22，CPU，纯离线）

基线 = V7 前端（`results/full-online-final.npz` 的 `t0`），全量 104,728 帧，统一评分器（与
`sweep.md` 的 1.4047 / 0.1876 逐位一致）。所有脚本在 `~/.dsh_scratch/moe_rot_20261022/`。

## 结论

MOE 不是被某个实现细节卡住的，它是**前端姿态估计的逐帧观测误差**（同地点跨日期不复现，也不是
地图带来的），而这套几何代价在 1–2 度的尺度上**对旋转没有梯度**。两者叠加的结果是：任何沿这张
代价面下降的改动都只能改善平移，而一旦真的去动旋转，反而会把误差推大。所以"MPE 全线改善、
MOE 不动"不是巧合，是同一个原因的两面。

## 1. MOE 不是长尾，是每一帧的常数级误差

| MPE 区间 | n | 占比 | 该区间 MOE | 占总 MOE |
|---|---|---|---|---|
| < 0.2 m | 83,662 | 79.9 % | 1.326 | 75.4 % |
| 0.2–0.5 | 19,488 | 18.6 % | 1.646 | 21.8 % |
| 0.5–1 | 893 | 0.9 % | 2.245 | 1.4 % |
| > 1 | 685 | 0.7 % | 3.03 | 1.3 % |

79.9 % 的帧位置误差已经在 0.11 米（中位 0.125 米），它们的 MOE 仍是 1.33 度，贡献了总 MOE 的
四分之三。所以削减灾难帧（>5 米那 290 帧）最多只能动 1.3 % 的 MOE——这不是一条能靠"修坏帧"
解决的路。全量中位 MOE 1.238 度，说明误差是逐帧均匀存在的。

## 2. 误差的构成与九种解释的排除

| 项目 | 值 |
|---|---|
| MOE | 1.405 度（中位 1.238，p90 2.46） |
| 偏航分量 \|yaw\| | 0.82 度（单轴标准差 1.27） |
| 俯仰/横滚分量 \|tilt\| | 0.99 度（横滚 1.08、俯仰 0.65） |

两个方向各占一半，所以只搜偏航（此前 `yaw_sweep`、`rot_coupling` 的做法）最多只能覆盖三分之一。
三个分量都是单峰连续分布，没有按候选集量化的痕迹。

| 假设 | 检验 | 结果 |
|---|---|---|
| 固定姿态偏差（外参/重力） | 求全局最优常量旋转后重算 | 最优常量 0.25 度，抵消后 1.405 → 1.380，只值 1.7 %，不是固定偏差 |
| 时间戳错位 | 用真值角速度回归 τ | τ = 0.03 秒，校正后 1.405 → 1.384，只值 1.5 % |
| 整帧延迟 | 对齐 ±1、±2 帧的真值 | 对齐 ±1 帧 MOE 变 3.8–4.0 度，没有延迟结构 |
| 平面对不齐（重力） | 把姿态 z 轴摆正到世界竖直 | 车辆在世界系里本来就前倾 2.8 度，摆正后 MOE 变 3.16 度，方向错 |
| 地图/地点本身的旋转 | 同一地点、不同日期的两帧误差是否一致 | 两地误差夹角 2.04 度，独立噪声预期 1.99 度，分量相关 +0.06——逐帧独立 |
| 扫描期运动畸变 | 误差与角速度的相关 | 相关系数 0.15；静止（<1 度/秒）时仍有 1.21 度 |
| 时间平滑（整体姿态） | 邻帧四元数平均 k=3/5/11 | 全部变差（1.40 → 1.42 → 1.52 → 2.03） |
| 时间平滑（只平滑倾斜，保留航向） | 平滑 z 轴、航向不动，k=3/5/9 | 同样变差（1.40 → 1.42 → 1.50 → 1.67）；真值的倾角本身每帧就变 1.19 度，没有可分离的慢变分量 |

九项全部否定。剩下唯一站得住的是：**姿态是逐帧独立、量级 0.8 度/轴、既无空间结构也无时间
结构的估计噪声，任何后处理都去不掉。** 注意"平滑救不了"不是方法问题：真值的倾斜方向相邻帧就
变 1.19 度，噪声和信号在同一频段上。

补充一条关键事实：参考库的 4752 帧来自 2012-01-22，不在四个真值日期内，所以参考位姿本身的姿态
误差无法直接测，用"同一地点另一天的误差是否重复"间接检验：前端 1.996 度对独立噪声预期 2.128 度，
图像 1.886 对 2.063（38 对同地点跨日期帧）——两者都基本不重复。所以**旋转误差不是地图带来的，
而是逐帧的观测误差**；把参考库换成姿态更准的来源也解决不了这一项。这条曾被我前一轮写成"杠杆在
参考库姿态"，现在纠正。

## 3. 几何代价对旋转没有信息（三个独立实验，180 + 150 帧分层样本）

| 实验 | 结果 |
|---|---|
| 平均截断最近邻代价 C(t0) vs C(真值) | 0.3499 vs 0.3818，真值只有 44/180 帧更优 |
| 换成点到面（地图法向）代价 | 0.2175 vs 0.2329，真值 29/150 帧更优 |
| 旋转景观（固定平移，逐轴扫 ±3 度） | 最小值就在 t0（各轴 63–78 % 的帧最优角为 0） |
| 代价斜率与真实误差方向的相关 | −0.01 / −0.08 / −0.09（点到面 +0.03 / +0.06 / +0.15） |
| **若用这代价做理想优化（逐轴取最优角）** | **MOE 1.405 → 1.99（点到面 1.51 → 1.87）** |

最后一行是决定性的：把这张代价面优化到底，旋转误差反而增大 40 %。也就是说"代价更低"与
"姿态更准"在这个尺度上是**反相关**的。配套的尺度感：±2 度旋转只让代价变动约 0.03 米（1.5 %），
而同样的代价变动对应 0.1 米级的平移——代价的主方向是平移，旋转方向是一条浅沟。

这也解释了 `truncation-cost-test` 的结论（换核函数无效）：问题不在截断或鲁棒核，在景观本身。

## 4. 对已有结果的解释

- `sweep.md` 里"旋转块一旦真的动就变差"（eps=1e-6 时 1.405 → 1.489，只有 eps ≥ 0.02 才回到
  基线）与上表完全一致：旋转块实际是在沿着这张代价面的噪声走。
- README 里 1502 帧 MOE 2.52 → 2.17 的改善，来源是**仲裁采纳了视觉候选**（18–29 帧换了整帧
  位姿），不是几何分支。全量 104,728 帧里这种帧极少，所以全量 MOE 停在 1.40。
- 视觉候选本身不是通用姿态源：冻结表里每帧最优候选的整体 MOE 是 13.0 度（偏航 12.0 度），
  只在仲裁挑中的少数帧上可用。

## 5. 图像能不能救旋转（单帧，已实测）

约束是"只用单帧、可以引入图像"，所以把图像当成第二个姿态测量源：几何分支给平移，
图像给旋转，两者按固定比例融合。做法是把视觉支路的位姿求解换成**只解旋转**——
相机中心已知（几何分支给到 0.11 米）时，每条 2D–3D 对应就变成一个"世界方向 → 相机方向"
的向量对，旋转是 Wahba 问题的闭式解，比六自由度 PnP 好条件得多。匹配、参考帧、LiDAR
投影关联全部沿用项目自己的实现，只换了最后一步。

| 项目 | 值 |
|---|---|
| 覆盖率 | 400 随机帧里 373–383 帧能给出对应（93–96 %） |
| 对应质量 | 内点中位 61 个，内点重投影残差中位 0.89 像素 |
| 前端姿态误差（同一样本） | 1.310 度 |
| 图像旋转误差，先验锚定解 | 1.693 度，与前端误差相关 **+0.79** |
| 图像旋转误差，无先验 RANSAC 解 | 1.921–2.011 度，与前端误差相关 **+0.37** |
| 两者误差之差 | 1.10 / 1.34 度（若互相独立应为 2.20 / 2.41 度） |
| 融合扫描（400 帧，锚定解） | λ=0.1 → 1.310；0.2 → 1.319；0.3 → 1.339；0.5 → 1.407；1.0 → 1.693 |
| 融合扫描（400 帧，无先验解） | λ=0.1 → 1.335；0.2 → 1.366；0.3 → 1.409；1.0 → 1.921 |
| 只在大部队上（311 帧，锚定解 λ=0.3） | 1.274 → 1.304，46 % 的帧变好（等于掷硬币） |

最小样本先说清楚：78 帧上曾看到 λ≈0.3 让 MOE 从 1.312 降到 1.217（提升 7 %，符号检验
p=0.0001），但把样本扩到 400 帧后这个改善消失了，λ 的最优点回到 0。所以那 7 % 是小样本
波动，不是效应。

两种解法把矛盾摊开了：锚定解（从前端姿态出发、逐级收紧门限）与前端相关 0.79，虽然本身更准
（1.69 度），但携带的是同一个误差，融合不降方差；无先验解的确更独立（0.37），代价是误差涨到
1.92–2.01 度，方差最优的融合比例只有 0.2 上下、理论增益 4 %，实测被尾部吃掉（λ=0.1 就变差）。
两条路都不通，原因是同一个：图像的内点三维坐标只能来自"参考帧关键点 → 参考帧自己的 LiDAR
回波"这条关联，它携带的是参考位姿的姿态。

这一步原来是推断，现在已经实测：取 38 对同一地点、不同日期的帧，比较各自的图像旋转误差。
若误差来自地图，同一地点的两次估计应该一致；实测"两次之差"是 1.886 度，而独立噪声的预期是
2.063 度（前端同一检验是 1.996 对 2.128）。**两者都不重复，说明既不是参考库、也不是地图的问题，
而是每一帧自己的观测误差**——所以"把参考库换成姿态更好的来源"并不能解决这一项。

更严格的三种改法也都试过，全部无效：

| 改法 | 结果 |
|---|---|
| 换 V8 微调权重 + 1024 关键点 + 10 参考帧（150 帧） | 图像误差反而涨到 2.50 度，融合更差（λ=0.2 时 1.377 → 1.524） |
| 只融合航向（去掉图像增量里的倾斜部分，保留前端的倾斜） | λ=0.2 时均值持平（1.310 → 1.312），中位略降 0.02 度，改善 49 %——掷硬币 |
| 按图像增量大小分组，只在大增量帧上融合 | 每一组、每个比例都变差；增量 >2 度的组在 λ=0.3 时直接涨 0.79 度 |

结论（这一节可以下定论的部分）：**在当前这套参考库下，单帧图像不能降低 MOE**，400 帧上任何
融合比例、任何分组、任何匹配器配置都不如不融合。

顺带给出一个可用的验收门槛，供以后改视觉支路时判断值不值得接：设前端旋转误差 σ_p、图像误差
σ_i、两者相关 ρ，融合的理论增益随 σ_i/σ_p 迅速衰减。以实测的 σ_p=1.31、ρ=0.37 代入，
σ_i 要到 **1.3 度左右**才有约 10 % 的增益，到 0.9 度约 20 %；现在的 1.7–2.0 度对应 4 %，
已经小于逐帧离散度，实测为 0。ρ 若高于 0.5，这条阈值还要再收紧。

## 6. 建议

1. **停止从几何分支里找旋转**。代价、核函数、搜索维度、旋转块、迭代轮次、切换代价、时间滤波，
   这一层已经到顶：任何改动都只能动平移。继续在这里投入不会改变 MOE。
2. **单帧图像目前也不行**，而且不是"匹配不够准"这一层能救的：把匹配换成 V8 微调权重、关键点
   加到 1024、参考帧加到 10 个之后，图像旋转误差从 1.69 涨到 2.50 度，融合反而更差。按第 5 节
   的验收门槛，图像误差要降到 1.3 度附近才谈得上 10 % 的增益。
3. **能降 MOE 的只剩姿态估计本身**。同地点跨日期的对照说明误差既不随地点重复、也不来自地图，
   而是每一帧的观测误差；地图、代价、参考库、时间滤波、图像融合都已排除。要真正降低 MOE，
   需要的是姿态精度更好的估计器（或一个能直接测姿态的传感器），不是这条链上任何一处后处理。
   验收门槛已给出：新姿态源的误差要显著低于 1.3 度，且与本前端不相关，才可能在融合后兑现。
4. 若最终不动姿态，论文里应把 MOE 写成"受前端姿态测量限制、本方法只做平移修正"，主张口径放在
   MPE、>1 米/>5 米计数上；注意"进一米两度"里的两度同样被 MOE 卡住——当前 80.6 % 的通过率里，
   卡在 1 米的只有 0.35 %，卡在两度的有 19.3 %。
