## 2. 数据流

```
初始位姿 T0（refined_V7）
   │
   ├─ 门控1  沿轨歧义比值 < 0.21 → 交给视觉候选支路（在搜索的地图上算）
   ├─ 沿轨搜索  粗筛 17×3（1000 点、首尾等间隔）→ 前 6 → 自适应展开（1500 点）
```

门控二（下降深度）默认关闭：自适应求解器把细筛压到约一个窗口之后，它省下的算力已经抵不上它丢的精度（见 3.2）。

## 3.1 统一判据下的三支编排

```
C(T) = 扫描点变换后到局部地图最近点距离的截断均值（截断 1 米）
T_leader ─► 粗筛代价面（17×3）                          每帧只算一次
              ├─ 歧义比值  ρ = (C_far − C_0)/C_0      → 要不要问另一个模态
              └─ 自适应细筛 → 平移修正（旋转保持不变）
视觉假设 ───────────────┴─► 同一份证据上更低者胜出，切换需付出 k·σ_C（σ_C 逐帧校准）
```

消融（全部在同一批 1502 帧、同一评分器、门控二关闭）：

| 配置 | MPE | MOE | 进一米两度 | >10 米 | >5 米 | 采纳视觉 |
|---|---|---|---|---|---|---|
| 只走路线三 | 1.5056 | 2.4839 | 746 | 7 | 19 | 0 |
| 旧仲裁（外部几何分数） | 0.8870 | 2.1664 | 749 | 3 | 12 | 29 |
| 统一仲裁 + 独立门 | 0.8623 | 2.1583 | 754 | 3 | 9 | 19 |
| **统一仲裁 + 合并门（默认）** | **0.8640** | **2.1663** | **754** | **3** | **9** | 18 |

合并门比独立门差 0.0017 米——这是"少两张地图"的价钱，判定上只差两帧。

切换代价 δ 的窗口：0.02 到 0.05 之间稳定，0 会放进"便宜但错"的候选，0.08 会漏掉灾难帧。
（2026-10-23 起 δ 已换成逐帧校准的 k·σ_C，默认 k=8.4，见 STRUCTURE.md；本段保留为历史记录。）

## 3.2 采样与求解器的同步（2026-10-21 补丁）

- **采点从"前 N 个"改成"首尾等间隔"**。扫描按采集顺序存放，前缀只覆盖一段方位；等间隔抽样把与旧门的一致率从 98.1% 提到 99.7%，且质量更好。
- **细筛从梯度剪枝改成自适应窗口展开**。旧剪枝的下界不成立（代价在 0.64 米步长上不线性，超出截断的点被当成常数），所以换成"按中心代价排序、只在中心代价接近最优时展开窗口"，实测 1502 帧与全展开逐位相同，但求值次数从 270 降到 79。
- 两项合起来：全搜索 MPE 1.6395 → 1.5056，端到端 0.9779 → 0.8640，单帧 0.245 → 0.22 秒。
- **副作用：门控二的尺度变了**。1000 点等间隔面上，下降深度的中位数从 0.0065 掉到 0.0000，全帧只有 44.7% 的增益为正；0.01 阈值只放行 31.5% 且精度变差（1.5703 对 1.5056）。所以默认 `--gate2 -1` 全帧搜索；若要省算力，`--gate2 0.001` 是新的工作点（0.9050 米、0.18 秒/帧）。

## 3.3 歧义门并入同一张地图

旧门每帧自己重建局部地图和 KD 树，那是它 350 毫秒里的大部分；共用搜索的地图后只剩 17 个位置的扫描（约 59 毫秒）。三个可复现的结论：点数是敏感量而沿轨步长不是（4000 点下 1 米与 0.5 米步长给出同样的 84 帧与 99.7% 一致；降到 2000 点则放行 138 帧、端到端崩到 1.283）；取点要等间隔不要前缀（98.1% → 99.7%）；门不能真的降到 0（粗筛点集换成门那套会让门控二的增益中位数掉到 0）。

## 5. 运行

```bash
cd /home/zhangcy/projects/e2e-moe-20261020-v1
python three_route_unified.py --workers 8                    # 默认：自适应+合并门+全帧搜索
```

`--mode` 切仲裁、`--gate` 切歧义门来源、`--solver` 切求解器、`--k` 是切换阈值（以校准出的
σ_C 为单位，默认 8.4，见 STRUCTURE.md）、`--gate2` 是下降门阈值（负数表示关闭）。
