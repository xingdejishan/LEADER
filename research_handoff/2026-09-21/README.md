# LEADER 多模态定位研究：固定证据快照

冻结日期：2026-09-21；这是一次完整研究交接，不是下一轮算法提案。

## 给研究 agent

用户希望你依据代码和实验事实独立思考一个更好的研究问题与方法。你可以重新定义研究切入点、质疑既有解释，也可以判断现有证据不足。这里不指定核心问题、融合层级、网络结构、损失、论文或下一步实验，不要求沿用当前方法。历史未通过的是具体配置与实验，不是整个方法类别的不可能性证明。

研究目标：在 LiDAR 地图定位任务中有效利用相机信息；当前工程评价目标为同时降低平移和旋转误差，并建立可信的视觉增益归因。方法创新及问题定位由你独立推导；已获授权的输入和评价边界见协议。

## 一次读取顺序

1. [CURRENT.md](CURRENT.md)：唯一现行状态、A/G/C/D/U/W定义和最终结果。
2. [EVIDENCE.md](EVIDENCE.md)：历史实验事实、可比性、原始结果直达链接。
3. [CODE_MAP.md](CODE_MAP.md)：固定代码和定位入口。
4. [PROTOCOL_AND_DATA.md](PROTOCOL_AND_DATA.md)：输入、评价、运行资源与缺失信息。
5. [per_frame.csv](per_frame.csv)：统一单位的192行逐帧评价；需要原字段时访问 evidence/current。

[独立研究请求](AGENT_REQUEST.md)可直接交给agent；所有清单内文件的字节哈希见[manifest.json](manifest.json)。代码来自同一天的本地现状，不要求寻找分支上的最新小版本；本快照所在Git提交本身就是版本锚点。

## 状态边界

A为固定比较基线；D是尺度修复后的稳健视觉参考路径；U为未通过标定验证的探索性路径，不是正式推荐方案。现有32帧是反复用于设计的开发集，尚无独立泛化结论。

只读分析不需要数据集/GPU。复跑需要未上传的原始图像、点云、标定、mask和权重；缺少资源已在协议中列明，无需为找本机路径消耗研究时间。evidence/history保留原始历史记录，但没有被列为核心证据的文件不自动拥有可信实验地位。

今后不要用微小改动覆盖本快照；新的研究结论另立完整快照或提交，并明确相对这份证据改变了什么。
