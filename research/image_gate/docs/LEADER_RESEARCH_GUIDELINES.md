# LEADER 研究与改进规范

## 1. 研究方式

1. 充分使用可用算力进行方法推理和方案比较，不局限于既有 REGOR 研究、用户曾提及的方法或当前代码结构。
2. 可以广泛检索相邻领域的文献，并吸收其中经过验证的理论、建模方式和推断方法。
3. 近三年（当前对应 2024—2026 年）的相关论文是正式实验前的重点阅读范围；必要时继续追溯群作用、鲁棒统计、最优实验设计、贝叶斯推断等基础理论，不受年份限制。
4. 理论与文献学习达到足以解释问题、比较已有方法并提出可检验假设的程度后，才开始设计改进方法。

## 2. 方法准入条件

在实现一个候选方向前，必须依次说明：

1. LEADER 的具体不足及其发生阶段；
2. 现有模块为什么不能充分解决该问题；
3. 新方法依赖的数学或统计理论；
4. 理论应具备的可检查性质，例如 yaw 不变性或等变性、可靠度校准、位姿可观测性、重复结构下的可辨识条件；
5. 由理论推出的可证伪预测；
6. 验证该预测所需的最小实验和停止条件。

不得因为某个信号在直觉上合理就直接加入模型。以 yaw、可信度、几何显著性或候选一致性为例，必须先解释它与最终位姿误差之间的理论关系，以及在什么条件下会失效。

## 3. 固定研究流程

每个研究方向按以下顺序推进：

`文献证据 → LEADER 失败机制 → 数学假设 → 必要条件诊断 → 单一 kill-test → 完整方法 → 冻结测试`

- 必要条件不成立时立即停止该方向，不通过堆叠模块或反复调参延长研究。
- kill-test 只验证一个核心命题，并提前确定成功条件和失败条件。
- 只有 kill-test 通过后，才实现完整训练、推理和消融链路。
- 不把 Oracle、候选容量、相关性或中间指标改善写成最终方法提升。

## 4. 目标与评价协议

1. 开始研究前明确目标属于以下哪一类：
   - NCLT/Oxford 同场景重定位精度；
   - 跨轨迹或跨季节鲁棒性；
   - 跨数据集泛化；
   - 运行效率或资源开销。
2. 训练集、开发集和最终测试集必须隔离；最终测试结果不得用于选择方法、超参数或停止轮次。
3. 数据划分、评价指标、随机种子、计算预算和通过条件应在正式测试前冻结。
4. 至少报告：
   - 平移与旋转误差的均值、中位数和尾部分位数；
   - 失败率或灾难性错误；
   - 逐序列结果；
   - rescue、damage 和净变化；
   - 可靠度校准指标（涉及可信度时）；
   - 推理时间、显存和参数量；
   - 与原方法同预算的关键消融。
5. LEADER 官方数据的训练和测试轨迹存在同环境空间重叠；除非另有独立证据，不得把同场景提升表述为跨场景泛化。
6. 用户于 2026-09-09 明确要求：有效的方法必须完成测试集全集验证，不能以小样本或中间指标结果作为最终交付。候选通过预先定义的端到端开发验证后，应冻结模型和参数，继续完成全量评测，不再把是否扩量作为可选步骤。
7. 当前 NCLT 的全集口径是与 v1 一致的 104735 帧官方测试清单，不能用 193/256 帧试验或 3560 帧图像抽样替代。多模态数据缺失必须报告覆盖率，并按预先定义的缺模态/拒绝策略保留全部查询的评价口径，不得仅报告可配对的有利子集。
8. 全量评测仍需与同协议 v1 对照，并报告整体及逐序列精度、尾部、成功率、rescue/damage 和耗时。已用于拟合或选型的官方测试帧必须单列为已接触数据；不能把包含这些帧的全量汇总称为独立盲测。已有完整且可核验的相同配置结果直接复用。

## 5. 算力与工程约束

1. 算力优先用于文献学习、理论推导、关键诊断和能够区分假设的实验。
2. 不频繁进行与当前假设无关的全仓库代码检查、重复静态扫描或大规模重放。
3. 代码检查只覆盖：
   - 与当前假设直接相关的执行路径；
   - 数据划分和标签泄漏；
   - 指标实现；
   - baseline parity；
   - 最终方法实际调用的模块。
4. 不生成无用的大量中间记录；只保留复现结论所需的配置、模型、核心日志、汇总指标和必要诊断工件。
5. 优先复用已有特征和中间结果；只有当缓存不完整、不可信或与新假设不兼容时才重新计算。
6. 代码资源采用最小实现原则：先复用现有入口，只为当前可证伪假设添加必要代码，不搭建通用框架、不做无关重构，不重复已通过且未受修改影响的检查。
7. 如服务器已有其他任务训练，保留其进程和正在使用的代码；独立研究使用单独命名的诊断文件，避免重复训练与结果覆盖。

## 6. 客观性要求

1. 明确区分理论保证、文献证据、项目内实验结果和推测。
2. 没有正向证据时直接报告没有，不将局部信号包装成完整改进。
3. 结果失败时保留失败结论和适用边界，不通过更名、选择性汇报或测试集调参重新包装。
4. 对新方法的评价以冻结后的完整端到端结果为准，而不是以实现复杂度、理论新颖性或计算投入为准。
5. “理论正确”指假设明确、推导成立、适用条件可检查、预测可证伪；数学推导不能代替对实际误差分布的验证。
6. 已用于比较或选择方法的测试样本视为开发证据，不能重新包装成未接触的最终测试；学习以能够解释失败机制、比较替代解释和设计判别实验为阶段完成条件。
